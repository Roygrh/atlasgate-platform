# Reconstructing Domain Workflow Discovery

This chapter records how fictional SES-005 documentation was produced. It does not reproduce private planning context and does not define a target workflow, requirement, architecture, or implementation.

## Method

1. Verify clean, aligned `main`; read repository guidance, all prior discovery records, governance/history, and the ignored private plan silently.
2. Bound the [session brief](../discovery/sessions/SES-005-domain-workflow-discovery/00-session-brief.md) around four distinct cases and explicit comparison questions.
3. Simulate 38 attributed exchanges in the [transcript](../discovery/sessions/SES-005-domain-workflow-discovery/01-simulated-transcript.md), preserving conflict, two unverified estimates, workarounds, ownership ambiguity, and owner-assigned evidence requests.
4. Extract `STMT-112` through `STMT-149`, then synthesize non-terminal `FND-028` through `FND-034` without analytical IDs inside dialogue.
5. Derive stable `DWF`, `DEP`, `HOF`, and `ADN` records from statements. Keep workflow, dependency, handoff, producer/consumer responsibility, and adoption need distinct.
6. Compare shared concerns with Commerce/Loyalty variation in [common versus domain-specific analysis](../discovery/domains/common-vs-domain-specific.md). A common concern is not evidence for an identical process.
7. Propagate only supported context to journeys, segments, hypotheses, outcomes, uncertainty, security/reliability records, risks, company/stakeholder context, indexes, history, and portfolio evidence.

## Stable records and validation posture

The [domain entry point](../discovery/domains/README.md) defines the record types. Workflows remain `Preliminary` or `Under validation`; dependencies, handoffs, and adoption needs remain non-terminal. Coordination is recorded separately from authority, deployment from completion, and producer responsibility from consumer adoption. Conflicts and unknowns remain visible in the [session record](../discovery/sessions/SES-005-domain-workflow-discovery/02-session-record.md) and [synthesis](../discovery/10-domain-workflow-discovery.md).

Validation checks Git scope and whitespace, repository-relative links, unique and sequential IDs, resolving references, participant coverage, allowed statuses, later-activity state, prohibited artifacts/claims, staging, branch, and private-plan isolation. Source-backed validation remains future work.

## Private-plan isolation

`atlasgate_project_master_plan.md` was read silently as private context. It was not modified, quoted, translated, staged, tracked, or used as public evidence. All tracked claims cite the fictional simulated session or earlier tracked evidence.
